# 지피터스 22기 1주차 수강 후기

> 📎 원문: [지피터스 1주차 후기](https://www.gpters.org/nocode/post/interface-development-week-1-NCK9Vqj4khZxQGm)

안녕하세요. 냐안의별입니다.

1주차 수업을 듣고, 정리한 글입니다.

---

## 수업 전 — 왜 신청했는가

저는 그동안 AI 도구를 꽤 여러 개 써왔습니다.

OpenClaw, Hermes, Claude Code, Codex, Gemini, NotebookLM 같은 것들이요.

도구마다 장점은 분명한데, 막상 제 일상이나 업무 흐름 안에서 자연스럽게 연결해서 쓰는 건 또 다른 문제더라고요.

특히 저는 맥미니를 AI 작업의 중심 환경처럼 사용하고 있습니다.

자동화나 AI 도구가 대부분 맥미니 안에서 돌아갑니다. 그런데 저는 늘 맥미니 앞에 앉아있는 건 아니거든요. 밖에서 핸드폰으로 뭐 좀 확인하거나 메모하거나 시키고 싶은 순간이 훨씬 많습니다.

그래서 머릿속에는 늘 같은 질문이 있었습니다.

> "어떻게 하면 핸드폰에서도 맥미니에서 직접 작업하는 것처럼 AI 도구들을 사용할 수 있을까?"

이번 강의 소개를 보면서 "인터페이스"라는 단어가 유난히 눈에 들어왔어요.

그동안은 도구 자체를 익히는 데 집중했다면, 이제는 그걸 어디서 어떻게 부를 수 있게 만들지가 더 중요하다고 느끼던 참이었거든요.

4주가 **기능 → 사용자 UI → 시스템 UI → 표준 UI** 순서로 한 겹씩 쌓이는 구성이라는 것도 좋았고, 특히 마지막에 API 서버랑 MCP 서버까지 연결한다는 부분에서 마음이 갔습니다.

---

## 수업 중 — 오늘 실제로 한 일

가장 먼저 자기소개와 수강 동기 라운드가 있었습니다.

다른 분들 이야기를 들으면서, 비슷한 결을 가진 분들이 모였다는 느낌이 들어서 좋았어요.

이어서 4주 커리큘럼 그림을 봤습니다.

기능(이번 주) → 사용자 UI → 시스템 UI → 표준 UI. 한 주에 한 계층씩 인터페이스를 얹어 나간다는 구조였는데, 이 그림이 머릿속에 박힌 게 오늘의 가장 큰 수확이었습니다.

라이브 실습 자체는 생각보다 간단했습니다.

터미널에서 폴더 하나 만들고 (`mkdir my-vault`), 그 폴더 안에서 Claude Code를 띄우는 것.

핵심 한 마디는 **"어디서 켜느냐 = Claude가 어느 폴더를 vault로 인식하느냐"** 였는데, 듣고 보면 당연한 말 같지만 평소에 그렇게 생각해본 적이 없었습니다. 저는 그동안 Claude Code를 앱으로만 써왔거든요.

다음으로 마크다운 4가지(헤딩, 리스트, 코드블럭, 링크)와 프론트매터 8필드를 다뤘습니다.

노트 한 장을 LLM이 잘 읽을 수 있도록 만드는 법이에요. 사람이 읽는 글과 LLM이 읽는 메타데이터를 한 파일에 같이 둔다는 발상이 신선했습니다.

라이브 2는 노트들을 어떻게 묶을지에 대한 이야기였습니다.

폴더로 나누는 계층형, 태그·링크로 평면적으로 묶는 제텔카스텐, 그리고 인덱스 노트가 모든 노트를 묶어주는 하이브리드(인덱스 위키). 결국 인덱스 위키 방식을 채택해서 실제로 만들어보는 흐름이었습니다.

마지막에는 자동화 파트가 있었습니다.

CLAUDE.md라는 파일을 vault 폴더에 두면 Claude가 자동으로 읽고 규칙을 따르고, 자주 쓰는 지시를 슬래시 커맨드(예: `/new-note`)로 만들어 두는 방식이었어요. 여기서 한 마디가 강하게 남았습니다.

> "2주차 텔레그램 봇이 호출할 게 바로 이 슬래시 커맨드들이다."

자동화가 한 그림으로 묶이는 느낌이 살짝 들기 시작했습니다.

수업은 안드레이 카파시 인용으로 마무리됐어요.

> "I want to write notes that LLMs can read." — Andrej Karpathy

사람과 LLM이 같은 파일을 읽는 시대.

오늘 만든 게 그 씨앗이라는 마무리가 인상에 남았습니다.

## 수업 후 — Q&A에서 들은 말로 생긴 향후 기대감

수업이 끝나고 따로 정리하다가, 머릿속 그림이 더 선명해진 부분이 세 가지 있어서 적어둡니다.

### Tailscale을 알게 된 것

3주차에 다룬다는 Tailscale을 미리 찾아봤습니다.

저는 지금까지 외부에서 맥미니에 접속할 때 TeamViewer로 화면을 공유해서 썼어요. 그런데 Tailscale은 화면을 공유하는 게 아니라, 네트워크 자체를 연결해주는 도구더라고요.

그러니까 핸드폰에서 맥미니의 API나 MCP 같은 서비스를 그냥 부를 수 있습니다. 화면 스트리밍이 없으니 데이터도 거의 안 쓰고, 배터리도 덜 닳는다고하는데 아직 설치만해놓고 써보진 않음. 그동안 막연히 "외부에서 맥미니 좀 쓸 수 있으면 좋겠다"였던 게, 진짜 답을 만난 느낌이었습니다. 이제해봐야죠.

### 터미널로 Claude Code를 쓰는 것의 의미

저는 지난 3개월 동안 Claude Code와 Codex를 앱으로만 써왔습니다. 헤르메스는 텔레그램이나 디스코드 봇으로 쓰고 있었고요.

그런데 수업이 끝날때 터미널을 쓰게되면 몰랐던 기능을 더사용할수 있다는 이재엽 랩장님 이야기를 듣고 이번기회로 한번사용해보기로했습니다. 오늘 알게 된 건, 앱과 터미널의 차이가 단순한 UI 차이가 아니라는 거였습니다.

써보면서 후기를 써보기로하겠지만 아직까지는 Claude Code 어플로 쓰는것이 훨씬 편하다는것입니다.

### 헤르메스 + Claude Code가 만나는 그림

지금까지 제가 쓰던 헤르메스 봇은 미리 정의된 명령만 받을 수 있었습니다.

그런데 4주 뒤에는 — 텔레그램 봇이 받은 자연어를 그대로 `claude` CLI에 흘려 보내면, Claude가 그때그때 알아서 해석하고 작업합니다. 노트 정리, 코드 분석, 어제 일지 요약 같은 걸 다 자연어 한 줄로 처리할 수 있는 거예요.

봇은 입출력 채널일 뿐이고, 두뇌는 Claude Code가 되는 구조.

정리하면 **맥미니가 1인 비서고, 핸드폰은 그 비서에게 말 거는 전화기**입니다.

이 그림이 오늘 가장 강하게 남은 메시지였어요.

## 마무리

거창한 서비스를 만든 건 아니지만, 제 AI 사용 방식을 자연스럽게 이어주는 구조의 첫 조각을 손에 쥔 느낌이 듭니다.

1주차에 Vault라는 기능 계층이 깔렸고, 다음 주부터 텔레그램, 그 다음 주에 Tailscale + API, 마지막 주에 MCP까지 한 겹씩 얹어 나갑니다.

지금까지 따로따로 쓰던 OpenClaw, Hermes, Claude Code, Codex가 4주 뒤에 한 환경 위에 얹혀서 핸드폰 하나로 자연스럽게 호출되는 그림 — 솔직히, 정말 기대됩니다.

그리고 이번 주 토요일에는 오프라인 미팅도 있다고 해서, 벌써부터 기대가 되네요. 온라인에서만 뵙던 분들을 직접 만나서 이야기 나눌 수 있다는 게 또 다른 재미일 것 같습니다.

다음 주에 뵙겠습니다.

냐안의별 이었습니다.
