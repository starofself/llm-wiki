# 미래에셋 → 한국투자증권 이관·자동매매 API 검토

> 요청: 미래에셋에서 API 자동매매가 어려워 한국투자증권으로 **계좌를 통째로 이관**하고 싶다. 전화 문의가 필요한지, 신용 잔고까지 옮길 수 있는지, 양사 API 후기를 커뮤니티까지 조사. 추가로 **자연어로 요청하면 프로그램매매·시간대별 일정수량 매매를 알아서 해주는 봇**을 만들 계획이며, **토스증권**이 만들고 있는 것도 함께 검토. (조사일 2026-05-24)

## 한 줄 결론

- **미래에셋은 개인용 자동매매 API가 사실상 막혀 있다.** 과거 시스템(AnyLink)은 2017년 7월 신규 접수 중단 상태라, "어렵다"고 느낀 건 실력 문제가 아니라 **구조적 한계**다.
- **한국투자증권 KIS Developers**는 무료 REST/WebSocket API + 모의투자 + 공식 GitHub 샘플 + **공식 MCP 서버**까지 제공하는, 현재 개인 자동매매의 사실상 표준이다. → **지금 갈아탈 1순위.**
- **토스증권 OpenAPI는 방향이 딱 맞는다**(REST+WebSocket, 미국주식 새벽 시간대 분할매매 자동실행, AI 연동 표방). 다만 **2026.5 사전신청 단계 / 정식오픈 미정 / 레퍼런스 부족** → 지금 메인으로 삼긴 이르고, **2순위 관찰**.
- **"통째로" 이관은 부분적으로만 가능.** 현금·현물 주식은 옮겨지지만 **신용융자 잔고는 이관 불가** → 미래에셋에서 상환 후 한투에서 신규 신용 약정.
- **"자연어로 알아서 매매"는 증권사 기능이 아니라 본인 봇이 만든다.** 증권사 API는 주문·시세·잔고만 주고, 자연어 해석·시간분할 스케줄링은 LLM(Claude 등)+봇 로직으로 직접 구현하는 구조다. (한투 공식 MCP도 "API 검색 도우미"일 뿐 매매 자동화가 아님 — 오해 주의)
- 출고 자체는 MTS에서 가능하지만, **신용 포함·대량·이관 이벤트 적용 건은 양사 고객센터에 미리 전화하는 게 안전**하다.

## 1. 왜 미래에셋에서 자동매매가 어려운가

| 항목 | 미래에셋증권 | 한국투자증권(KIS Developers) |
|---|---|---|
| 개인용 OpenAPI | **AnyLink** 플러그인 방식 — **2017.7.10 신규 신청 중단** | REST API + WebSocket (2022.4~) |
| 방식 | 구형 Plug-in/연동형, 사실상 신규 사용 어려움 | HTTP 기반, OS 무관 |
| OS | 사실상 Windows 종속 | **Linux/클라우드(AWS EC2) OK** → 24시간 무인 운영 |
| 모의투자 | 제공 | 제공(단 호출 제한 낮음, 실전계좌 권장) |
| 공식 샘플 | 빈약 | **GitHub 공식 레포** + AI/MCP 연동 도구 |
| 비용 | - | API 이용료 없음, 매매수수료는 HTS와 동일 |

미래에셋의 `AnyLink`는 "시세조회·잔고조회·주문연결용 Plug-in"이며 **신규 신청이 2017년부터 막혀 있다.** 즉 일반 개인이 새로 자동매매 API를 붙이는 건 현실적으로 불가능에 가깝다. 커뮤니티(클리앙)에서도 원글 작성자가 "미래에셋 API 미지원 때문에 증권사 이전을 고려한다"는 게 글의 배경이었다.

## 2. 커뮤니티 후기 종합

**클리앙 / 인프런 / 블라인드 / 개발 블로그**에서 모은 평가:

- **한국투자증권**: "한투 API가 가장 좋지 않을까", "REST라 파이썬 requests만으로 동작", "AWS EC2에서 24시간 운영 + 디스코드 알림, 만족도 최상". 가장 현대적이라는 중평.
- **키움증권**: 자료·레퍼런스가 가장 많음. 단 전통적으로 COM/OCX(Windows) 기반이라 환경 제약.
- **대신증권 / 이베스트(LS증권)**: 전산 강자, 이베스트는 최근 REST+WebSocket OpenAPI 출시로 "파이썬 개발 편하다"는 평.
- **미래에셋**: API 미지원이 갈아타기의 주된 사유로 반복 등장.

**한투 API 단점(미리 알아둘 것)**
- **초당 최대 20건 호출 제한(Rate Limit)** → 다수 종목 동시 처리 시 설계 필요(분할 호출/우선순위).
- 모의투자 계좌는 호출 제한이 더 낮아 파라미터 최적화엔 실전계좌 권장.

## 3. "통째로 이관"이 실제로 어디까지 되나

옮기는 행위 = **타사대체출고**(받는 쪽 입장에선 타사대체입고).

| 자산 종류 | 이관 가능 여부 |
|---|---|
| 현금(예수금) | 일반 이체로 이동 |
| 일반 현물 주식(국내) | **가능** — 종목 단위로 대체출고 |
| 해외 주식 | 가능하나 절차 번거로움(지점/유선, 1~2일) |
| **신용융자 잔고** | **불가** — 옮길 수 없음 |
| 대출/담보 주식, 미수 상태 | 사실상 불가, 먼저 정리 필요 |

### 신용 잔고 처리 순서 (중요)
사용자가 "신용도 가질 거라 통째로 옮기고 싶다"고 했는데, **신용은 통째 이관이 안 된다.** 절차는:
1. 미래에셋에서 신용융자 **상환**(현금 상환 or 매도) → 순수 현물·현금 상태로 정리
2. 현물 주식을 한투로 **타사대체출고**
3. 한투에서 **신용거래 약정을 신규 체결** 후 다시 신용 사용

> 신용을 유지한 채로는 못 옮기므로, 신용 비중이 크면 이관 타이밍(상환 부담·매도 시 세금/손익)을 따로 계산해야 함.

## 4. 절차 · 비용 · 시간

- **출고 신청**: 기존 증권사(미래에셋) MTS/HTS → "타사대체출고"/"주식이체" 메뉴. 해외주식은 지점 방문/유선.
- **필요 정보**: 옮길 종목, 받는 증권사명(한국투자증권), **한투 계좌번호**, (지점 시) 신분증.
- **출고 수수료**: 종목당 약 **1,000~3,000원**(미래에셋 기준 확인 필요). 한투 안내상 대체출고 수수료/징수금 부족 시 신청이 취소될 수 있음.
- **소요시간**: 국내주식 거의 실시간, 해외주식 1~2일.
- **주의**: 오전 처리 권장(일부 14시 마감), 지점 방문 전 전화 필수.

## 5. 한국투자증권 이관(주식 옮기기) 이벤트

한투는 **국내주식 타사입고 이벤트**를 상시/주기적으로 운영(순입고 규모별 상품권·매수쿠폰). 자료 시점별로 혜택이 **70만원 ~ 최대 501만원**까지 다르게 표기됨 → **현재 조건은 반드시 직접 확인**.
- 보통 **이관 후 일정 기간 순입고 금액 이상 유지** 조건이 붙음.
- 해외주식은 별도 이벤트가 없거나 약한 편.
- KB·키움 등도 경쟁 이벤트를 하므로 **이관 직전 시점에 비교**하면 혜택 극대화 가능.

**한국투자증권 1544-5000 — 확인할 것**

**미래에셋증권 1588-6800 — 확인할 것**

- 보유 종목 타사대체출고 수수료/마감시간

## 7. 추천 액션 순서

1. **한투 계좌 + KIS API 앱키부터 발급**받아 모의투자로 자동매매를 **먼저 검증** (이관 전에 "정말 쉬운지" 확인)
2. 검증되면 → 한투 **이관 이벤트 조건 확인**
3. 미래에셋 **신용 상환 → 현물 정리**
4. **타사대체출고**로 현물 이동, 이벤트 유지조건 충족
5. 한투에서 신용 약정 재개

## 8. 토스증권 OpenAPI (신규 검토 대상)

2026년 5월 21일, 토스증권이 **OpenAPI 사전신청**을 시작했다(기존 계좌 보유 고객 대상, 정식 오픈일 미정).

| 항목 | 내용 |
|---|---|
| 방식 | **REST API + WebSocket** (설치 불필요, OS/기기 무관) |
| 자동매매 | 국내외 주식 통합 인터페이스로 자동화 |
| **시간분할 매매** | **미국주식 야간(새벽) 시간대 분할 매매 전략 자동 실행** 명시 ← 사용자가 원하는 "시간대별 일정수량 매매"와 정확히 일치하는 방향 |
| AI 연동 | ChatGPT·Claude 등 LLM 연결, "내 포트폴리오 수익률 분석" 같은 자연어 명령 표방 |
| 수수료 | 국내주식 2026년 6월까지 면제(기존 계좌 요율) |
| 키 발급 | 토스증권 PC 웹에서 API 키 발급 |
| 비공식 도구 | `JungHoonGhae/tossinvest-cli`("토스증권을 AI 에이전트에 연결") |

**평가**: 표방하는 방향(AI 친화 + 새벽 분할매매)은 사용자의 목표와 가장 잘 맞는다. 단 **출시 직후라 레퍼런스·안정성·실사용 후기가 거의 없다.** 지금 당장 봇을 올리는 메인 인프라로는 위험하고, **사전신청만 걸어두고 정식 오픈/후기 확인 후 도입**하는 게 합리적. (참고: 한투가 해외주식 REST API로 시장 선점, 키움도 멀티 OS REST API 출시 → 토스는 후발 추격자 구도.)

## 9. "자연어로 알아서 매매하는 봇" 설계 관점

사용자 목표: **텔레그램봇에 자연어로 명령** → 봇이 명령을 파악 → **시간대별로 수량·가격을 정해 매매 주문을 봇이 직접 발주.** 핵심은 **증권사가 그 기능을 주는 게 아니라, 텔레그램봇 = 명령 입구, 내 봇 = 주문 집행자**라는 점이다. (사용자는 이미 텔레그램 vault 봇을 운영 중 → 같은 패턴 확장 가능)

**구조**
```
[텔레그램 명령]      →  [LLM 파서:Claude] →  [매매계획 생성]        →  [스케줄러]      →  [주문엔진] → [증권사 REST API]
 "삼성전자 1만주를      종목=삼성전자          09:00·09:30·…·15:00      각 슬롯 시각에     체결확인·     KIS/토스 주문
  오전 9시부터 30분      총수량=10000          슬롯당 1000주             도달하면 발주      재시도·       (초당 20건 제한)
  마다 천주씩 사줘"      방식=시간분할          가격=시장가/지정가         트리거            잔고반영
                        + 가격조건            (사용자 지정대로)                          → 텔레그램 회신
```

- **명령 입구는 텔레그램봇.** 사용자가 채팅으로 자연어 명령 → 봇이 즉시 수신.
- **명령 파악(NLU)은 LLM(Claude) 몫.** "오전 9시부터 30분마다 천주씩" → {시작 09:00, 간격 30분, 슬롯수량 1000, 종목, 매수/매도, 가격조건}으로 구조화. 모호하면 텔레그램으로 되물어 확정(휴먼 컨펌).
- **시간대별 수량·가격 매매명령은 봇의 스케줄러가 자동 발주.** 슬롯 시각이 되면 주문엔진이 증권사 API로 주문을 쏘고, 체결/미체결·잔고를 텔레그램으로 회신. (증권사는 예약/조건주문 정도만 기본 제공하므로 분할·스케줄링은 봇이 담당)
- 증권사 API는 결국 **주문·시세·잔고 호출**만 담당. → REST가 깔끔하고 레퍼런스 풍부 + 모의투자 가능한 곳이 절대 유리.
- **안전장치 필수**: 실매매이므로 ① 발주 전 텔레그램 확인 버튼 ② 일/슬롯 최대수량·금액 한도 ③ 모의투자에서 충분히 검증 후 실전 ④ 장애 시 자동 중단(kill-switch) ⑤ 모든 발주·체결 로깅.

**증권사별 봇 적합도**

| | 한국투자증권 | 토스증권 | 미래에셋 |
|---|---|---|---|
| REST/WebSocket | O (성숙) | O (신규) | △ (AnyLink, 신규중단) |
| 공식 MCP/LLM 예제 | **O** (공식 MCP + LLM 샘플 + 전략빌더·백테스팅) | 표방(미공개) | X |
| 모의투자 | O | 미정 | 제한적 |
| 레퍼런스·커뮤니티 | **최다** | 거의 없음 | 적음 |
| 자연어 봇 시작점 | **즉시 가능** | 오픈 후 | 비추 |

> **주의**: 한투 공식 MCP(`koreainvestment-mcp`)는 "삼성전자 현재가 API 찾아줘"처럼 **API 문서를 자연어로 검색**해주는 도우미다. 실제 시세조회·주문·자동매매 로직은 **직접 구현**해야 한다. "MCP 깔면 자연어로 매매 끝"이 아님.

**권장 스택**: `한투 KIS REST API` + `Claude(자연어 파싱)` + `Python 스케줄러/주문엔진`. 모의투자로 분할매매 로직 검증 → 실전. 토스는 정식 오픈 시 미국주식 새벽 분할매매 용도로 추가 검토.
