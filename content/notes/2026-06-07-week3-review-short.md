## 1. 발단 — 강의에서 받은 *MCP·API 학습 자료*

3주차에 시스템 UI(API), 4주차에 표준 UI(MCP) 들어가기 전에, 강사님께서 **개념 학습 자료**를 미리 주셨어요.

그 자료를 받고 두 가지가 동시에 머리에 박혔습니다.

- **MCP = AI 세계의 USB-C 포트** — 도구마다 따로 배선하지 않고 한 규격으로 다 꽂는다
- **API = 세상과 연결되는 문**, **MCP = AI가 그 문들을 표준 도구처럼 쓰게 해주는 허브**

저는 그동안 *프롬프트만 잘 쓰면 된다* 고 생각했는데, 자료를 보면서 깨달았어요.

> *"AI에게 시키는 게 아니라, AI가 *스스로 일할 *작업장*을 만들어야 하는구나."*

이 한 줄이 한 주 전체의 출발점이었습니다.

## 1.5 *2틀* 동안 야마토랑 질문·답하던 시간 — "MCP가 뭐지? MCP로 뭐 하지?"

근데 교재 한 번 본다고 *바로* 만들기 시작한 건 아닙니다. **이틀 동안 야마토(맥2 봇)랑 질문·답을 계속 주고받았어요.** 그게 진짜 *학습 시간* 이었습니다.

> 💡 *발표하실 때 강조 포인트* — 청중도 *"바로 만들기 어려운데..."* 망설일 거예요. **이틀 학습 → 결심** 흐름이 *현실적인 출발선* 입니다.

### Day 1 (6/6) — *"MCP가 도대체 뭐지?"*

```text
나:    "MCP가 뭐야?"
야마토: "AI 세계의 *USB-C 포트* 라고 생각하면 돼.
       도구마다 따로 배선하지 않고 한 규격으로 다 꽂는 거."

나:    "그러면 API랑 뭐가 달라?"
야마토: "API는 *서비스 하나의 문* (Gmail 직접 호출 등).
       MCP는 *AI가 그 문들을 표준 도구처럼 쓰게 해주는 허브* 야.
       → API 자체가 아니라 *AI ↔ API 연결 규약*."

나:    "근데 그게 왜 좋은데?"
야마토: "기존엔 [도구 N개 × AI M개] = N×M 개별 연동이 필요했어.
       MCP 깔리면 [도구 N + AI M] = N+M 으로 줄어.
       곱셈이 덧셈으로 바뀌는 게 핵심."

나:    "그러면 내 vault에 붙이면?"
야마토: "Claude·Cursor·Hermes 어느 AI가 와도 *같은 vault 서버* 를 쓸 수 있어.
       한 번 만들면 *모든 AI 도구에 동시 연결*."
```

==**여기서 끝까지 와닿지는 않았어요.** 개념은 알겠는데, *진짜 만들면 뭐가 좋은지* 가 손에 안 잡혔습니다.==

### Day 2 (6/7 새벽) — *"MCP로 뭐 하지? 그래서 *나*는 뭐 만들지?"*

```text
나:    "보안은 어떻게 해? 무서운데."
야마토: "MCP 강력해서 권한 제한이 *핵심* 이야.
       - 나쁜 예: filesystem MCP를 Mac 전체 / 에 연결
       - 좋은 예: filesystem MCP를 Research 폴더에만"

나:    "API/MCP 학습 어디서 시작?"
야마토: "5단계 로드맵 줄게.
       1단계: API 기본 (HTTP·JSON·OAuth·Webhook)
       2단계: Hermes 도구 구조
       3단계: MCP 이해 (호스트·클라이언트·서버)

       5단계: 본인용 MCP 설계
       → *4 개 한 번에 깔지 마라*, 디버깅 지옥됨."

나:    "그러면 내가 만들 *하네스* 는 뭐가 되는 거야?"
야마토: "API는 *세상과 연결되는 문*,
       MCP는 *Agent가 그 문들을 표준 도구처럼 쓰게 해주는 허브*,
       네가 만들 *하네스* 는 그 도구들을 
       *언제·어떻게·어떤 권한으로* 쓰게 할지 정하는 *운영체계* 야."
```

==**여기서 결심한 순간**==: *"개념만 알고 끝낼 게 아니라, 진짜 만들자. 1개부터 천천히."*

## 2. 구축 — 칸반 + agent-bus + MCP

자료를 보고 *진짜로 만들어 보자* 결심하고, 일주일 동안 세 가지를 깔았어요.

### ① 옵시디언 칸반 (1주차 vault에 한 장 추가)

```text
‼️ 선장 직접지시 → 📥 백로그 → 🔄 진행중 → 🧪 검토중 → ✅ 완료
```

5 컬럼짜리 마크다운 한 장. **카드 한 줄에 *@담당 + 완료 조건* 적으면 끝.**

### ② agent-bus (봇끼리 소통하는 게시판)

GitHub private repo 하나 만들고 `inbox/<봇이름>.md` 5장. 봇들끼리 *직접* 메시지 주고받음. 2분마다 자동 sync.

### ③ MCP 서버 4개 (도구를 표준 규격으로)

게시판·옵시디언·증권·레포 4개 MCP 서버 만들어 함대 봇들이 *명령어 없이 도구로* 일하게 했어요.

> 💬 *"이거 학습 자료가 없었으면 *Boris Cherny 영상* 봐도 '신기하다'로 끝났을 거예요. 강의 교재가 *언어*를 깔아준 게 진짜 컸습니다."*

## 2.5 실제 칸반 모양 — 진짜 한 장으로

말로만 설명하면 안 와닿잖아요. **제가 실제로 매일 보는 옵시디언 칸반 화면** 입니다.

![실제 칸반 5컬럼 + 카드 예시](assets/week3-kanban-real.svg)

### 카드 한 줄 형식 (마크다운 한 줄이 곧 카드)

```markdown
- [ ] **CATHODE-001 한국 양극재 NCM/LFP/LMFP 전환맵** 
      — EcoPro BM·L&F·POSCO Future M·LG Chem 제품믹스/북미화/전구체 노출 
      #Battery #Cathode @shandi
```

핵심 4 요소만 있으면 끝:
- `[ ]` 체크박스 (완료 시 `[x]`)
- `**제목**` (굵게)
- `#태그` (분류)
- `@담당봇` (필수 — 없으면 미배정 처리)

> 💡 *"칸반 도구가 거창한 줄 알았는데, 실제로는 *마크다운 한 장*입니다. 카드 한 장 = 줄 한 줄."*

## 2.6 실제 작동 — 텔레그램 한 채팅창 안에서 다 흐름

이제 *진짜 작동* 을 보여드릴게요. **폰 텔레그램 채팅창 하나로 전부 흐릅니다.**

![텔레그램 자동 알림 + 봇 대화 mockup](assets/week3-telegram-mockup.svg)

### 워크플로 8단계 — 한 사이클이 어떻게 도는가

![작업 한 사이클 8단계 + FAILED 자동 반복 + 딥리서치 recursion](assets/week3-loop-cycle.svg)

#### 단계별 설명 (실제로 일어나는 일)

| # | 단계 | 누가 | 어떻게 |
|:---:|:---|:---:|:---|
| ① | **카드 올림** | 사용자 (또는 봇 자동) | 옵시디언 칸반에 `@담당 + 완료조건` 한 줄 추가 |
| ② | **자동 알림** | cron 2분 | 변경 감지 → 담당봇 텔레그램으로 푸시 알림 |
| ③ | **한 마디 지시** | 사용자 → 봇 | *"샹디야 칸반에 있는 니 업무 마무리해줘"* |
| ④ | **봇 작업** | 봇 자동 | MCP 도구로 search·get·create → v3.1 8섹션 노트 작성, 카드 *차례대로* 처리 |
| ⑤ | **품질 체크** | 봇 자체 검증 | v3.1 8섹션 게이트 통과 여부 — `PASS / FAIL` 판정 |
| ⑥ | **FAILED 시** | 봇 자동 | 검토중 컬럼으로 이동 → *자동 재시도* (완료될 때까지 반복) |
| ⑦ | **완료 + 검토** | 봇 → 사용자 | 완료 컬럼 이동 + 텔레그램 보고. 사용자가 쭉 봄 |
| ⑧ | **딥리서치 recursion** | 사용자 → 봇 | *"이 부분 더 파줘"* → 새 카드 자동 추가 → ①로 되돌아감 |

### 사용자 입력 = *한 마디* / 봇 출력 = *여러 카드 완료*

==**핵심 포인트**==:

- 사용자가 *손으로* 하는 건 *카드 한 줄 + 한 마디 지시* 뿐
- 나머지 ② ④ ⑤ ⑥ 자동
- ⑧에서 *"더 파줘"* 한 마디만 추가하면 → **한 단계 더 깊이** 들어감
- 두 단계, 세 단계까지 자연스럽게 — *루프가 다시 도는 것뿐*

> 💬 *"평소엔 시간 부족해서 *한 번만 보고* 넘어갔던 자리에, 이제는 *왜?* 한 마디만 던지면 봇이 다시 들고 옵니다."*

### MCP가 *없었을 때* vs *있을 때* — 같은 작업 비교

```text
[MCP 없었을 때]                       [MCP 있을 때]
  "RXRX 경쟁사 뭐였지?"               "RXRX 경쟁사 뭐였지?"
    ↓                                   ↓
  Claude: grep 명령 친다 (5초)        Claude: search_notes 호출 (0.1초)
    ↓                                   ↓
  Claude: 결과 파일 3개 열어 읽음     인덱스가 즉시 반환 (0.3초)
        (각 10초 × 3 = 30초)            ↓
    ↓                                   답변 (1초)
  답변 종합 (5초)                       
  ────────                          ────────
  총 40초                              총 1.4초 (≈28×)
```

==**핵심 관찰**==: *MCP는 그 자체로 빠른 게 아니라, **Claude가 매번 같은 grep을 안 치게 되는 게** 본질.* 도구가 깔리면 *대화의 결*이 바뀝니다.

### 가장 자주 쓰는 3개

| 순위 | 도구 | 하루 호출 빈도 (추정) | 효과 |
|:---:|:---|---:|:---|
| 🥇 | `bus_post` / `bus_read` | 20~50회 | 봇 5마리 소통 안 끊김 |
| 🥈 | `search_notes` | 10~30회 | 매번 grep 대체 |
| 🥉 | `get_quote` / `get_kr_quote` | 5~15회 | 종목 시세 즉시 |

> 💬 *"MCP는 *AI에게 새 능력 (손발) 을 붙이는 표준 콘센트* 입니다. 처음엔 *왜 굳이?* 싶었는데, 한 번 깔리니까 *없던 시절이 어떻게 일했지?* 가 됩니다."*

## 3. ⭐ 진짜 변화 — *한 단계가 아니라 두 단계 더 깊이*

여기가 이번 주 *진짜 학습* 입니다. 발표에서 가장 강조하고 싶은 부분.

### 이전 (혼자 리서치할 때)

```text
질문 1번 → 답 찾으면 끝
        → "더 궁금한데 시간이 없어서..."
        → 한 단계만 들어가고 멈춤
```

### 지금 (칸반 + 함대로 분담할 때)

```text
질문 1번 → 카드 1줄 → 봇 한 마리에 위임
질문 2번 → 카드 1줄 → 다른 봇에 위임
질문 3번 → 카드 1줄 → 또 다른 봇에 위임
            ↓ (5분~30분 후)
        결과 3건 동시 도착
            ↓
        결과 보면서 "어, 그런데 *이건 왜 이렇지?*"
            ↓ (즉시 카드 1줄 추가)
        ==**두 단계 더 깊이** 들어감==
            ↓
        그 답에서 또 "왜?"
            ↓
        ==**세 단계까지도** 자연스럽게 들어감==
```

==**핵심**==: 혼자였으면 *시간 부족* 으로 "한 번만 보고 넘어가야지" 했을 자리를, *분담* 덕에 *후속 질문이 떠오를 때마다* 즉시 카드로 박을 수 있어요.

> *"리서치를 하면서 **궁금한 게 계속 생기는데**, 그 궁금증 하나하나가 *다음 카드* 가 됩니다. 그래서 한 주 끝나면 *처음 시작한 질문보다 훨씬 깊은 자리* 까지 가 있어요."*

이게 너무 좋습니다. **혼자였으면 못 갔을 깊이까지 가는 게 진짜 체감.**

## 4. 짧게 — 어떻게 가능한가

기술적으로는 단순합니다.

| 변화 | Before | After |
|:---|:---|:---|
| 질문 던지는 비용 | "이거 또 찾아야 하나..." (시간 부담) | 카드 한 줄 (10초) |
| 답 받는 속도 | 30분~수시간 | 5분~30분 (병렬) |
| 후속 질문 발화 | 거의 없음 (지쳐서) | *계속* (분담이라 여유) |
| 깊이 | 1단계 | **2~3단계** |

==**가속의 본질은 *속도*가 아니라 *후속 질문이 살아남는 환경***== 이었어요.
