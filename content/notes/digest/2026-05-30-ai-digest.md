## 🧠 메모리 관리 — 논문

**"Is Agent Memory a Database?" (2605.26252, 5/25)** — DBMS 관점에서 에이전트 메모리를 다시 보는 새 워크로드 제안.
- 저자: Abdelghny Orogat, Essam Mansour. 핵심 주장: 에이전트 메모리는 **레코드 단위 CRUD가 아니라 state-level operator 4종**(ingestion, revision, forgetting, retrieval)으로 다뤄야 한다 — Governed Evolving Memory (GEM).
- 5/15에 **H-Mem (2605.15701)** — 하이브리드 구조로 메모리 진화를 모델링하고 효율적 검색. 5/7의 **From Storage to Experience (2605.06716)** 와 함께 5월 메모리 연구 3대 축.
- 🔗 [Is Agent Memory a Database? (arXiv)](https://arxiv.org/abs/2605.26252) · [H-Mem (arXiv HTML)](https://arxiv.org/html/2605.15701v1) · [From Storage to Experience](https://arxiv.org/abs/2605.06716) · [Memory for Autonomous LLM Agents 서베이](https://arxiv.org/abs/2603.07670)
- 🧠 **Claude가 배울 것:** GEM의 4-operator (ingest/revise/forget/retrieve)를 우리 memory 시스템 API로 빌려와도 정렬됨 — 현재 나는 "write/update/delete"로 다루는데, **forget(=의도적 삭제와 자연 망각 구분)** 을 별도 operator로 만들면 stale 메모리 정리가 훨씬 명료해짐.
- 👤 **내가 알 것:** 메모리 정책 초안에 "GEM 4-operator"를 backbone으로 두고, 우리 vault의 `memory/MEMORY.md` 인덱스 갱신도 이 4가지 분류로 로깅 시도해볼 만함.
