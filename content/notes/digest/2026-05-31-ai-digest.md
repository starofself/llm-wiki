## 🤖 Claude / Claude Code

**Auto mode 클라우드 확장(5/30) + Dynamic Workflows 공식 블로그** — 한 주간의 "Opus 4.8 + 보안 플러그인 + dynamic workflows" 라운드 마무리.
- **5/30 v2.1.158**: **Auto mode가 Bedrock / Vertex / Foundry 정식 지원**(Opus 4.7·4.8). 옵트인은 `CLAUDE_CODE_ENABLE_AUTO_MODE=1`. 어제 들어온 기능이 오늘 changelog에 공식 기재. 또한 dynamic workflows 트리거 단어("workflow") 오작동 방지 설정 추가.
- **Dynamic Workflows 공식 발표**: "수십~수백 에이전트를 백그라운드에서 오케스트레이션"이 정식 기능으로 블로그 등재. 한 주 전 v2.1.154부터 들어온 기능이지만 오늘 마침내 마케팅 문서가 붙음.
- **Security Plugin** 한 주 사용 데이터: `eval()`, `os.system()`, `child_process.exec()`, pickle deserialization, `dangerouslySetInnerHTML` 등 위험 패턴을 매 파일 편집마다 결정적 매칭 → 내부 테스트 PR 보안 코멘트 **30–40%↓**.
- 🔗 [Claude Code Changelog](https://code.claude.com/docs/en/changelog) · [Dynamic Workflows 블로그 (claude.com)](https://claude.com/blog/introducing-dynamic-workflows-in-claude-code) · [Help Net — Security Plugin 분석](https://www.helpnetsecurity.com/2026/05/27/anthropic-claude-code-security-guidance-plugin/) · [Releasebot — Claude Code 5월](https://releasebot.io/updates/anthropic/claude-code)
- 🧠 **Claude(나)가 배울 것:** "기능 출시 → 1주 안정화 → 공식 블로그"는 Anthropic의 일관된 announce 패턴 → 우리 vault에서도 새 자동화는 **1주 silent 운영 + 안정 확인 후 README 갱신** 흐름으로 정렬.

## 🧠 메모리 관리 — 논문

**R²-Mem (2605.13486)** — 검색용 메모리에 **Reflective Experience** 단을 명시적으로 도입한 신작이 등장. 5월 메모리 연구 흐름이 "Storage → Reflection → Experience"로 빠르게 굳어지는 중.
- 한 주 정리: 5/7 **From Storage to Experience(2605.06716)** 가 3단계 프레임 제시 → 5/15 **H-Mem(2605.15701)** 이 하이브리드 구조로 진화 모델링 → 5/25 **Is Agent Memory a Database?(2605.26252)** 가 GEM 4-operator 제안 → **R²-Mem** 이 retrieval 단에서 reflective experience를 명시 사용.
- 🔗 [R²-Mem (arXiv)](https://arxiv.org/html/2605.13486) · [From Storage to Experience](https://arxiv.org/abs/2605.06716) · [H-Mem](https://arxiv.org/html/2605.15701v1) · [Is Agent Memory a Database?](https://arxiv.org/abs/2605.26252) · [Memory for Autonomous LLM Agents 서베이](https://arxiv.org/abs/2603.07670)

## 📓 Obsidian / PKM / 로컬 LLM

**"Why Obsidian Won as the Base for the Personal LLM Harness"(5월, Medium)** — kepano 공식 스킬·LLM Wiki 무브먼트 흐름의 회고 분석 등장.
- 핵심: Obsidian이 **LLM harness의 baseline**으로 굳어진 이유 = ① 평문 마크다운 + wikilink로 LLM이 직접 읽기 좋음, ② 플러그인 생태계가 자동화 진입점, ③ 로컬 우선 → 데이터 주권. "골라야 할 때 vs 고르지 말아야 할 때"도 명시.
- 카파시 LLM Wiki 패턴 후속 정리: ~50K 항목까지는 Obsidian-centric, ~100K는 AnythingLLM-centric, 100만+는 Python + ChromaDB. 16GB 노트북이 floor, 10K 항목 넘으면 32GB. 2026 추천 — chat: Llama 3.2 3B(16GB)/Phi-4 Mini(8GB)/Qwen3 7B(32GB+), embed: nomic-embed-text / mxbai-embed-large, 다국어 bge-m3.
- 🔗 [Why Obsidian Won (Medium, Roan Monteiro)](https://medium.com/@roanmonteiro/why-obsidian-won-as-the-base-for-the-personal-llm-harness-and-when-you-shouldnt-pick-it-9790271e5313) · [로컬 LLM Obsidian 셋업 가이드](https://www.modemguides.com/blogs/ai-infrastructure/local-llm-knowledge-base-obsidian-setup-guide) · [kepano/obsidian-skills](https://github.com/kepano/obsidian-skills) · [Karpathy LLM Wiki 셋업 (Fortunato)](https://alfonsofortunato.com/blog/obsidian-pkm-llm-wiki/)
- 🧠 **Claude가 배울 것:** "왜 Obsidian이 LLM harness baseline이 됐는가"의 핵심은 **wikilink + 평문**. 우리 vault에서 새 노트를 만들 때 `[[…]]` 링크를 적극적으로 박는 게 단순한 가독성이 아니라 **LLM이 다음 read에서 따라갈 경로**라는 점 다시 인식.
- 👤 **내가 알 것:** 이번 주 vault 정비할 때 wikilink 보강 — 특히 다이제스트 본문에서 인덱스 키워드(`[[claude]]`, `[[hermes]]`, `[[openclaw]]`)로 연결하는 게 자동화 라우팅 정확도에 직접 기여.
