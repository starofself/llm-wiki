## 🧠 메모리 관리 — 논문

**MemCog (2605.28046, 5/28)** — "memory-as-tool → memory-as-cognition" 패러다임 전환을 명시한 신작. 5월 메모리 흐름의 정점이자 6월의 시작점.
- 한 줄: 사용자 지식을 **Navigable Memory Store**로 조직, **associative link graph**로 메모 간 연결을 저장하고 메모리 접근 자체를 추론의 일부로 통합. 검색 단(R²-Mem) → 데이터 구조 단(MemCog)으로 추상화가 한 칸 올라간 셈.
- **5월 한 달 메모리 논문 정리** (이번 주말 백본으로 묶기 좋은 시점):
  - 2605.03354 *What Happens Inside Agent Memory?* (회로 분석)
  - 2605.05583 *Belief Memory* (부분관측 하 멀티 후보 메모)
  - 2605.06716 *From Storage to Experience* (3단계 프레임)
  - 2605.10870 *Remember the Decision, Not the Description* (rate-distortion)
  - 2605.13486 *R²-Mem* (reflective experience)
  - 2605.26252 *Is Agent Memory a Database?* (4-operator)
  - 2605.28046 *MemCog* (associative link graph)
- 🔗 [MemCog (arXiv)](https://arxiv.org/abs/2605.28046) · [R²-Mem](https://arxiv.org/abs/2605.13486) · [From Storage to Experience](https://arxiv.org/abs/2605.06716) · [Belief Memory](https://arxiv.org/abs/2605.05583) · [Remember the Decision](https://arxiv.org/abs/2605.10870) · [Is Agent Memory a Database?](https://arxiv.org/abs/2605.26252)
- 🧠 **Claude가 배울 것:** MemCog의 **associative link graph**가 우리 vault의 `[[wikilink]]`와 정확히 같은 구조 — 메모리를 "리스트"가 아니라 "엣지가 있는 그래프"로 본다는 시그널. `MEMORY.md`에 평면 리스트로 항목을 쌓는 대신, 각 메모 파일이 다른 메모를 **`[[다른-메모-이름]]`으로 적극 링크**하도록 정책 업그레이드. 가이드 항목 본문에 명시 권장.
- 👤 **내가 알 것:** 5월 7편이 한 그래프로 묶이는 그림이 보임 (Storage→Reflection→Experience 축 + DB/회로/부분관측 가지). 이번 주말에 `notes/memory-policy-2026-06.md`로 backbone 노트 한 편 작성 적기.
