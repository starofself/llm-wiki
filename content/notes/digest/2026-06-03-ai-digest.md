## 🧠 메모리 관리 — 논문

에이전트 메모리 서베이가 우리 `memory/` 정책의 backbone. 핵심 축은 **write–manage–read 루프**. 6월에도 후속 정밀화 논문이 이어짐.
- **Memory for Autonomous LLM Agents (2603.07670)** — 메모리를 write–manage–read 루프로 정형화, 시간범위·표현기질·제어정책 3차원 분류 + 5개 메커니즘 패밀리(컨텍스트 압축·검색증강 스토어·반성적 자기개선·계층적 가상컨텍스트·정책학습 관리). 2022~2026초 커버.
- **Adaptive Memory Admission Control (2603.04549)** — 메모리에 *쓰기 전* 신뢰성·사실성 검증으로 **잘못된 기억의 입력 자체를 게이팅** (admission control).
- **ActMem (2603.00026)** — "기억함"과 "잘 씀" 사이의 간극, 즉 **검색–추론 연결**을 메움. **AgeMem (2601.01885)**은 장·단기 메모리 관리를 정책에 통합해 메모리 연산을 툴 액션으로 노출.
- 🔗 [Memory Survey (arXiv)](https://arxiv.org/abs/2603.07670) · [Adaptive Memory Admission Control (arXiv)](https://arxiv.org/pdf/2603.04549) · [ActMem (arXiv)](https://arxiv.org/pdf/2603.00026) · [Agentic Memory / AgeMem (arXiv)](https://arxiv.org/pdf/2601.01885)
- 🧠 **Claude가 배울 것:** **Admission Control = "쓰기 전 검증"**은 내 `MEMORY.md` 운영 규칙(중복 점검·틀린 메모 삭제)의 학술적 근거. 저장 시점에 한 번 거르는 습관 강화 — 어제 "기억 주권" 논의의 *무엇을 쓸지* 축과 직결.
- 👤 **내가 알 것:** 메모리 정책 초안(`notes/memory-policy-2026-06.md`)에 서베이 + admission control(쓰기 게이팅) + 검색–추론(ActMem)을 묶어 backbone으로 — 이월 TODO 보강.

## 📓 Obsidian / PKM / 로컬 LLM

- 🔗 [Karpathy LLM Wiki 셋업 (Alfonso Fortunato)](https://alfonsofortunato.com/blog/obsidian-pkm-llm-wiki/) · [로컬 LLM KB 구축 가이드 (modemguides)](https://www.modemguides.com/blogs/ai-infrastructure/local-llm-knowledge-base-obsidian-setup-guide) · [LLM Wiki 플러그인 (Obsidian Forum)](https://forum.obsidian.md/t/new-plugin-llm-wiki-turn-your-vault-into-a-queryable-knowledge-base-privately/113223)
