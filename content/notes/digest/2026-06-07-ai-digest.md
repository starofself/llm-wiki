## 🤖 Claude / Claude Code

**SpaceX 컴퓨트 딜로 한도 또 2배** — Anthropic이 SpaceX Colossus 1 데이터센터 전체 용량(300MW+, NVIDIA GPU 22만 장 이상)을 확보하면서 Claude Code 5시간 한도를 또 2배로 올리고 Pro·Max 피크타임 감축을 폐지. Opus 모델 API 레이트리밋도 대폭 상향.
- **Opus 4.8 출시**: 4.7 대비 코딩·에이전트·추론·실무 지식 강화. Fast 모드 기본값이 Opus 4.8($10/$50 per MTok, 표준 2배 가격에 ~2.5배 속도).
- **ultracode 설정**: effort 메뉴에서 접근, effort를 xhigh로 두고 Claude가 워크플로 사용 시점을 자동 판단. fallback 모델·deny-rule glob 확대·크로스세션 메시지 보안 강화도 추가.
- **Claude Partner Network**: 6/3 Services Track·Partner Hub 출범. Opus 4.1은 API에서 은퇴 예고(6/5 통지).
- 🔗 [Higher limits + SpaceX 딜 (Anthropic)](https://www.anthropic.com/news/higher-limits-spacex) · [Claude Code 한도 2배 (Engadget)](https://www.engadget.com/2166315/anthropic-is-doubling-claude-code-rate-limits-after-deal-with-spacex/) · [Claude 업데이트 (Releasebot)](https://releasebot.io/updates/anthropic/claude) · [Changelog](https://code.claude.com/docs/en/changelog)
- 🧠 **Claude(나)가 배울 것:** `ultracode`/effort 자동 판단은 우리 다이제스트 같은 반복 작업에 "언제 워크플로를 띄울지"를 모델에 맡기는 패턴 — 능동성 룰(v1.4)과 결이 같다.
- 👤 **내가 알 것:** 5시간 한도가 ==또 2배==. SpaceX GPU 22만 장 덕이다. 맥미니호 더 빡세게 굴려도 됨. Fast 모드는 이제 Opus 4.8이라 품질 손해 없이 빠름.

## 🔷 Gemini / Antigravity (Gemini CLI 종료 D-11)

**Gemini CLI 6/18 종료까지 D-11** — 6/18부터 AI Pro·Ultra·무료 티어 대상 Gemini CLI/Code Assist IDE 확장이 요청 처리 중단. Antigravity CLI(Go 재작성, 클로즈드소스)로 이관. Code Assist Standard/Enterprise 라이선스 조직은 영향 없음.

- 🔗 [Gemini CLI→Antigravity 이관 (Google)](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/) · [6/18 종료 (The Register)](https://www.theregister.com/ai-ml/2026/05/20/bye-bye-gemini-cli-google-nudges-devs-toward-antigravity/5243605) · [마이그레이션 가이드 (AI Builder Club)](https://www.aibuilderclub.com/blog/google-kills-gemini-cli-june-18-2026)

- 👤 **내가 알 것:** ==D-11.== Gemini CLI 쓰는 워크플로 있으면 6/18 전에 점검. 클로즈드소스 전환 + 패리티 미달이라 오픈소스 팬덤 반발 중.

## 🧠 메모리 관리 — 논문

에이전트 메모리 서베이가 계속 쏟아짐 — 우리 파일 기반 `memory/`와 직결.
- **Memory for Autonomous LLM Agents (2603.07670)** — 메모리를 *write–manage–read 루프*로 정형화, 시간범위·표현기질·제어정책 3차원 분류. 5개 메커니즘 패밀리(컨텍스트 압축·검색증강 스토어·반성적 자기개선·계층 가상컨텍스트·정책학습 관리) 심층 분석.
- **From Storage to Experience (2605.06716)** — Storage→Reflection→Experience 진화 3단계 서베이.
- **Mnemonic Sovereignty / 기억 주권 (2604.16548)** — LTM 보안을 Write·Store·Retrieve·Execute·Share 6단계 라이프사이클로, 메모리 포이즈닝·추출·검색 오염·제어흐름 하이재킹·교차에이전트 전파·롤백·거버넌스 정리.
- 🔗 [Memory Survey (arXiv)](https://arxiv.org/abs/2603.07670) · [From Storage to Experience (arXiv)](https://arxiv.org/abs/2605.06716) · [Mnemonic Sovereignty (arXiv)](https://arxiv.org/abs/2604.16548)
- 🧠 **Claude가 배울 것:** "반성적 자기개선(reflective self-improvement)" 패밀리가 핵심 — 메모를 단순 적재가 아니라 주기적으로 다시 읽고 정제하는 루프로 운영.
- 👤 **내가 알 것:** 우리 파일+MEMORY.md 인덱스 방식은 "검색증강 스토어 + 라우팅" 패밀리에 해당. 다음 과제는 보안(포이즈닝·교차전파 방어).

## 📓 Obsidian / PKM / 로컬 LLM
