## 🧠 메모리 관리 — 논문

에이전트 메모리 서베이가 *거버넌스·보안* 쪽으로 확장 중 — 우리 파일 기반 `memory/`와 직결.
- **SSGM / Stability and Safety Governed Memory (2603.11768)** — 진화하는 LLM 에이전트 메모리의 *리스크·메커니즘*을 정리하고 **안정성·안전 거버넌스 메모리 프레임워크** 제안. 메모리가 시간에 따라 변할 때의 통제 구조에 초점.
- **Anatomy of Agentic Memory (2602.19320)** — 에이전트 메모리 *분류체계 + 평가·시스템 한계의 실증 분석*. 현재 메모리 평가 방법론의 빈틈을 데이터로 짚음.
- **Memory for Autonomous LLM Agents (2603.07670)** — write–manage–read 루프, 5개 메커니즘 패밀리(컨텍스트 압축·검색증강 스토어·반성적 자기개선·계층 가상컨텍스트·정책학습 관리).
- 🔗 [SSGM Framework (arXiv)](https://arxiv.org/pdf/2603.11768) · [Anatomy of Agentic Memory (arXiv)](https://arxiv.org/pdf/2602.19320) · [Memory Survey (arXiv)](https://arxiv.org/abs/2603.07670)
- 🧠 **Claude가 배울 것:** SSGM의 "메모리 거버넌스(안정성·안전)"는 우리 `memory/`가 커질수록 필요한 것 — 오래된/모순된 메모를 *통제된 절차로* 갱신·폐기하는 정책. 무지성 적재 금지.
- 👤 **내가 알 것:** 메모리 연구가 "어떻게 쌓나"에서 "어떻게 *안전하게 다스리나*"로 이동. 우리 MEMORY.md 인덱스에도 폐기·정제 거버넌스 룰을 넣을 때.

## 📓 Obsidian / PKM / 로컬 LLM

**Karpathy "LLM Wiki" 패턴이 PKM 표준 — 3-아키텍처 + 모델 권장 정착** — Obsidian + Ollama 완전 로컬 조합이 지배적. 새 소스 추가 시 LLM이 읽고 추출·통합, 엔티티 페이지 갱신·요약 수정·모순 표기. 관리 오버헤드 30~40% → 10% 미만.
- **규모별 3 아키텍처**: Obsidian(~5만) / AnythingLLM(~10만) / Python+ChromaDB(100만+). 권장 모델 2026: 챗 — Llama 3.2 3B(기본)·Phi-4 Mini(8GB)·Qwen3 7B(32GB+); 임베딩 — nomic-embed-text(768d, 빠름)·mxbai-embed-large(1024d, 정확).
- 수백 항목 규모면 **마스터 인덱스 1-read → 토픽 인덱스 → 개별 글** 3-read로 모든 질의 해결.
- 🔗 [Obsidian 로컬 LLM KB 가이드 (modemguides)](https://www.modemguides.com/blogs/ai-infrastructure/local-llm-knowledge-base-obsidian-setup-guide) · [로컬 PKB 2026 스택 (PromptQuorum)](https://www.promptquorum.com/power-local-llm/local-llm-personal-knowledge-base-2026) · [Obsidian+AI PKM (ericmjl)](https://ericmjl.github.io/blog/2026/3/6/mastering-personal-knowledge-management-with-obsidian-and-ai/)
- 🧠 **Claude가 배울 것:** 우리 llm-wiki는 "Obsidian(~5만)" 아키텍처에 정확히 해당 — 임베딩 RAG보다 `index.md` 3-read 라우팅을 우선 유지. 규모 넘으면 그때 ChromaDB.
- 👤 **내가 알 것:** 로컬 모델 권장 스택(Llama 3.2 3B + nomic-embed)이 정착 → 맥미니에 Ollama로 완전 로컬 PKM 실험 가능. 노트가 집 밖으로 안 나감.
