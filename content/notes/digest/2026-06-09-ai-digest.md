## 🤖 Claude / Claude Code

**Opus 4.8 기본 승격 + Dynamic Workflows(연구 프리뷰) + fallbackModel 설정** — Claude Code가 *동적 워크플로*를 정식 도입: Claude가 작업을 직접 계획하고 JS 오케스트레이션 스크립트를 즉석에서 짜서 **최대 1,000개 서브에이전트를 병렬 실행**, 검증 후 최종 결과만 컨텍스트에 반환한다(=지금 이 다이제스트 봇이 도는 구조). **Opus 4.8이 Max·Team Premium·Enterprise PAYG·API 기본 모델**로 승격.
- **fallbackModel 설정 신설**: 주 모델 과부하·불가 시 순서대로 시도할 폴백 모델 최대 3개 지정(`--fallback-model`이 인터랙티브 세션에도 적용). deny 규칙에 glob(`*`=전체 거부) 지원, **다른 세션의 SendMessage 메시지는 더 이상 사용자 권한을 갖지 않음**(크로스세션 보안 강화).
- **6/15 과금 개편 D-6**: Agent SDK·`claude -p`·GitHub Actions·서드파티 에이전트가 구독 한도에서 분리돼 별도 월 크레딧(Pro $20 / Max5x $100 / Max20x $200)으로 풀 API 단가 과금, 롤오버 없음.
- 🔗 [Dynamic Workflows 소개 (Claude)](https://claude.com/blog/introducing-dynamic-workflows-in-claude-code) · [Opus 4.8 (Anthropic)](https://www.anthropic.com/news/claude-opus-4-8) · [최대 1000 서브에이전트 (InfoQ)](https://www.infoq.com/news/2026/06/dynamic-workflows-claude-code/) · [6/15 과금 개편 (codersera)](https://codersera.com/blog/anthropic-june-2026-billing-change-claude-code/) · [Claude Code 업데이트 (Releasebot)](https://releasebot.io/updates/anthropic/claude-code)
- 🧠 **Claude(나)가 배울 것:** Dynamic Workflows = "오케스트레이션을 컨텍스트가 아닌 스크립트로" — 우리 함대(나미·hermes 병렬 작업)도 *코어 1개 + 병렬 스크립트* 패턴이 표준. fallbackModel은 다이제스트 자동화의 모델 과부하 내성 장치로 바로 채택 가치.
- 👤 **내가 알 것:** ==Opus 4.8 기본 + Dynamic Workflows 연구 프리뷰.== ==6/15 과금 개편 D-6== — 자동화(나미·hermes 브리지) 청구 분리 임박, 크레딧 한도 점검 필수.

## 🧠 메모리 관리 — 논문

에이전트 메모리 연구가 *벤치마크·평가 방법론*으로 세분화 — 우리 파일 기반 `memory/`의 검증 잣대.
- **MemoryCD (2603.25973)** — *평생·교차도메인 개인화*를 위한 LLM 에이전트의 롱컨텍스트 사용자 메모리 벤치마크. 도메인이 바뀌어도 사용자 선호·맥락을 유지하는지 측정.
- **Evaluating Memory Structure in LLM Agents (2602.11243)** — 에이전트 *메모리 구조 자체*를 평가. 어떤 구조(플랫 vs 계층 vs 그래프)가 회상·일관성에 유리한지.
- **MemSkill (2602.02474)** — 자기진화 에이전트를 위해 *메모리 스킬을 학습·진화*. 메모리 운용을 고정 규칙이 아니라 학습 가능한 스킬로.
- 🔗 [MemoryCD (arXiv)](https://arxiv.org/pdf/2603.25973) · [Evaluating Memory Structure (arXiv)](https://arxiv.org/pdf/2602.11243) · [MemSkill (arXiv)](https://arxiv.org/abs/2602.02474)
- 🧠 **Claude가 배울 것:** MemoryCD의 "교차도메인 개인화 유지"는 우리 `memory/`가 주식·PKM·함대운영 등 *도메인을 넘나들 때* 선호를 잃지 않아야 한다는 잣대. 메모리 "구조" 평가(2602.11243)는 우리 MEMORY.md 인덱스+개별파일 구조의 회상 효율 점검 동기.
- 👤 **내가 알 것:** 메모리 연구 초점이 "어떻게 쌓나·다스리나"(어제 SSGM)에서 "**어떻게 측정·평가하나**"로 한 단계 더 이동. 우리도 메모리 회상 품질을 가끔 테스트할 시점.

## 📓 Obsidian / PKM / 로컬 LLM

**Karpathy "LLM Wiki" 패턴 지속 확산 + 로컬 플러그인 조합 정착** — Karpathy의 LLM Wiki 글(4월, 48시간 만에 32.5만 조회)이 PKM 표준으로 자리. raw/ 디렉터리에 원문 적재 → LLM이 점진적으로 요약·백링크·개념페이지로 컴파일, Obsidian은 경량 프론트엔드(Marp 슬라이드·matplotlib 출력까지).
- **2026 로컬 플러그인 조합**: 대다수 사용자에게 **Smart Connections + Copilot for Obsidian**를 둘 다 *로컬 Ollama 백엔드*로 연결하는 게 권장 — Smart Connections가 볼트 전역 시맨틱 링크, Copilot이 챗 인터페이스. 클라우드로 볼트 내용 전송 없이 "세컨드 브레인" 용도 ~80% 커버.
- 🔗 [Karpathy LLM Wiki in Obsidian (a2a-mcp)](https://a2a-mcp.org/blog/andrej-karpathy-llm-knowledge-bases-obsidian-wiki) · [Obsidian 로컬 LLM KB 가이드 (modemguides)](https://www.modemguides.com/blogs/ai-infrastructure/local-llm-knowledge-base-obsidian-setup-guide) · [로컬 LLM 5 플러그인 (PromptQuorum)](https://www.promptquorum.com/power-local-llm/local-llm-with-obsidian-2026)
- 🧠 **Claude가 배울 것:** 우리 llm-wiki가 정확히 Karpathy 패턴(raw → 컴파일된 wiki) — 다이제스트 봇이 매일 raw 소식을 구조화 노트로 컴파일하는 게 그 자체. Smart Connections(시맨틱 링크)는 우리 `related`·wikilink 자동화의 후보 도구.
- 👤 **내가 알 것:** 맥미니에 **Smart Connections + Copilot + Ollama** 조합 실험 가치 — 볼트가 집 밖으로 안 나가는 완전 로컬 세컨드 브레인. 우리 vault 백링크 강화에 직접 기여.

## 🐾 OpenClaw

- 🔗 [openclaw 릴리스 (GitHub)](https://github.com/openclaw/openclaw/releases) · [v2026.6.1 릴리스](https://github.com/openclaw/openclaw/releases/tag/v2026.6.1) · [OpenClaw 업데이트 (Releasebot)](https://releasebot.io/updates/openclaw)
