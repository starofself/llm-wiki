## 🧠 메모리 관리 — 논문

**MemRefine (arXiv 2606.13177, 6/11)** — 장기 에이전트 메모리의 "무한 팽창 + 중복 엔트리" 문제를 LLM 판사로 해결. 표면 유사도만으로 후보 쌍을 추천하고, 실제 삭제·병합·유지 결정은 LLM이 사실적 가치 기준으로 판단. 예산 제약 환경에서 성능 유지하며 목표 메모리 용량 달성.

- **Agent Memory: Characterization (arXiv 2606.06448, 6/4)** — 에이전트 메모리의 첫 시스템 특성화 연구. 시스템 지향 분류체계 + 10개 시스템 벤치마킹. 시스템 권고 10종(스케줄링·용량 바닥·쿼리 볼륨 상각·신선도-지연 트레이드오프·플릿 스케일 관리).
- 🔗 [MemRefine (arXiv)](https://arxiv.org/abs/2606.13177v1) · [Agent Memory 시스템 특성화 (arXiv)](https://arxiv.org/abs/2606.06448v1) · [Memory Survey 2603.07670 (arXiv)](https://arxiv.org/abs/2603.07670)
- 🧠 **Claude가 배울 것:** MemRefine의 "유사도=후보 추천, LLM=가치 판단"은 우리 메모리 정제 정책의 실전 알고리즘. 내 MEMORY.md 스태일 항목을 주기적으로 LLM 판단으로 정리하는 루프 검토.
- 👤 **내가 알 것:** 메모리 시스템 벤치마크 논문(2606.06448)의 권고 10종 — 우리 파일 기반 메모리에 "쿼리 볼륨 상각" + "신선도 vs 지연" 설계 기준이 적용 가능.

## 📓 Obsidian / PKM / 로컬 LLM

**Obsidian Bases v1.13.x — 오프라인 DB가 완성형** — Notion 스타일 데이터베이스 뷰가 완전 오프라인으로 동작. Ollama 연동으로 로컬 LLM 완전 에어갭 PKM 구현 가능(노트가 외부 서버로 안 나감).

- **3-아키텍처 수렴**: ①Obsidian 중심(노트 우선, ~5만 항목까지), ②AnythingLLM 중심(문서 우선, ~10만 항목), ③Python+ChromaDB(엔지니어링, 100만+ 항목) — 실용적 빌드의 95% 커버.
- Karpathy LLM Wiki 패턴(raw→정제→구조화 마크다운 위키) + LLM 자동화로 큐레이션 오버헤드 80~90% 감소.
- 🔗 [Obsidian 2026 완전 가이드 (Oflight)](https://www.oflight.co.jp/en/columns/obsidian-knowledge-management-guide-2026) · [로컬 LLM KB 구축 가이드 (ModemGuides)](https://www.modemguides.com/blogs/ai-infrastructure/local-llm-knowledge-base-obsidian-setup-guide) · [Karpathy LLM Wiki 패턴 (a2a-mcp)](https://a2a-mcp.org/blog/andrej-karpathy-llm-knowledge-bases-obsidian-wiki)

- 👤 **내가 알 것:** Bases 오프라인 = 구독 없이 데이터 완전 로컬 유지. AnythingLLM이나 ChromaDB로 스케일업 필요 시점 기준(~5만 vs ~10만 항목)을 기억해둘 것.
