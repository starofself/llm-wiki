## 🤖 Claude / Anthropic — ⚠️ Fable 5·Mythos 5 정부 정지 명령

**사상 최초 AI 모델 수출 통제** — 6/12 미 상무부가 Fable 5·Mythos 5에 대해 수출 통제 디렉티브를 발동. 외국 국적자(미국 내·외국 내 불문)의 모든 접근을 즉시 차단하라는 명령. Anthropic은 실시간 국적 검증이 불가능하다는 이유로 전 세계 고객 접근을 일제 비활성화. **AI 모델 자체에 수출 통제가 적용된 것은 역사상 처음.**

- 정부 주장: 모델 가드레일을 우회하는 탈옥 방법이 발견됨
- Anthropic 반박: 해당 탈옥은 좁은 범위이고, 다른 공개 모델로도 이미 재현 가능한 수준
- Claude Code 측 업데이트(별도): `wheelScrollAccelerationEnabled` 설정 추가(풀스크린 스크롤 가속 제어), `/cd` 세션 이동, 중첩 서브에이전트 자체 서브에이전트 생성, 안전 모드(broken config 격리)
- 🔗 [Anthropic 공식 성명](https://www.anthropic.com/news/fable-mythos-access) · [CNBC 보도](https://www.cnbc.com/2026/06/12/anthropic-disables-access-to-fable-5-and-mythos-5-to-comply-with-government-directive.html) · [The Hacker News](https://thehackernews.com/2026/06/anthropic-releases-claude-fable-5-its.html) · [Claude Code Changelog](https://code.claude.com/docs/en/changelog)
- 🧠 **Claude가 배울 것:** 모델 자체가 수출 통제 대상이 된 전례 — 앞으로 고성능 모델을 쓰는 API 설계 시 "국적 기반 접근 제어"가 요구 사항이 될 수 있다. 정부 개입 가능성을 아키텍처 리스크로 인식해야 함.
- 👤 **내가 알 것:** Fable 5·Mythos 5 현재 전면 사용 불가. Fable 5 무료 윈도우 기간(~6/22)은 사실상 정지 상태. 정부 디렉티브 해제 시 재활성화 예정이므로 공식 발표 주시. Claude Code의 중첩 서브에이전트(5단계) + safe mode는 계속 사용 가능.

## 🔷 Gemini / Antigravity — ⚠️ CLI 종료 D-1 (내일!)

**Gemini CLI 내일(6/18) 종료** — 잔여 시간 ~24시간. Google AI Pro·Ultra·무료 Gemini Code Assist 개인 사용자는 내일부터 `gemini` 명령이 응답을 반환하지 않음. Antigravity CLI(`agy`)로 마이그레이션 완료하지 않았다면 **오늘 안에 처리 필수.** Antigravity CLI는 Go 기반으로 Gemini CLI보다 응답이 빠르고, 복잡한 리팩터·멀티 리서치를 백그라운드 멀티 에이전트로 병렬 처리.

- 유료 Gemini Code Assist Standard/Enterprise, 또는 Gemini Enterprise Agent Platform API 키 사용자는 영향 없음
- Antigravity Agent Skills / Hooks / Subagents / Extensions = 기존 Gemini CLI 기능의 플러그인 형태로 계승
- 🔗 [Google Developers Blog 공식 발표](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/) · [마이그레이션 가이드 (DigitalApplied)](https://www.digitalapplied.com/blog/gemini-cli-to-antigravity-cli-migration-june-18-2026-guide) · [Gemini Code Assist 릴리스노트](https://developers.google.com/gemini-code-assist/resources/release-notes) · [The Register](https://www.theregister.com/ai-ml/2026/05/20/bye-bye-gemini-cli-google-nudges-devs-toward-antigravity/5243605)
- 🧠 **Claude가 배울 것:** Antigravity의 "백그라운드 멀티에이전트 병렬 처리" 패턴은 우리 Dynamic Workflows와 같은 설계. CLI→에이전트 플랫폼으로의 전환이 업계 표준으로 수렴 중.
- 👤 **내가 알 것:** 스크립트·CI에서 `gemini` 호출하는 부분 오늘 반드시 점검. `agy` 바이너리로 교체 후 4가지 breaking 변경사항(모델명/스트리밍포맷/상태디렉토리/종료코드) 확인.

## 🟢 OpenAI / GPT — GPT-4.5 은퇴 D-10, GPT-5.6 출시 임박

**GPT-4.5 6/27 은퇴 카운트다운** — GPT-5.5가 현재 ChatGPT 기본 모델. GPT-4.5는 이달 말(6/27) 공식 은퇴 예정. GPT-5.6은 6월 중 출시설이 돌고 있으나 공식 날짜 미확정. GPT-6(장기 메모리 헤드라인 피처)는 Q3-Q4 2026 이후로 전망 이동.

- GPT-5.2 이미 은퇴 완료(6/12) → 기존 GPT-5.2 대화는 자동으로 GPT-5.5로 이어짐
- GPT-5.6 개선 방향: 추론 정밀도 향상, 반복 자율 작업 강화, 토큰 효율 개선
- GPT-6: 아직 아키텍처 논문·파라미터·가격표·출시일 미공개 상태
- 🔗 [ChatGPT 릴리스노트 (OpenAI)](https://help.openai.com/en/articles/6825453-chatgpt-release-notes) · [GPT-5.6 전망 (Geeky Gadgets)](https://www.geeky-gadgets.com/gpt-5-6-june-2026-release/) · [GPT-6 타임라인 (lifearchitect.ai)](https://lifearchitect.ai/gpt-6/)
- 🧠 **Claude가 배울 것:** GPT-5.6 "토큰 효율" 트렌드는 나도 불필요한 출력 최소화 방향과 일치. GPT-6 장기 메모리가 "차기 핵심 피처"로 지목된 것은 우리 파일 기반 메모리 시스템의 방향이 옳다는 신호.
- 👤 **내가 알 것:** GPT-4.5 기반 API·스크립트 있으면 GPT-5.5로 교체 D-10. GPT-5.6 출시 시 다이제스트 즉시 반영 예정.

## 🧠 메모리 관리 — 논문

**Mnemonic Sovereignty (arXiv:2604.16548, 4월) — LTM 보안의 6단계 프레임워크** — 에이전트 장기 메모리(LTM)를 "가변적·재작성 가능·사회적 전파 가능"으로 규정하고 메모리 라이프사이클 전 과정의 보안을 다루는 서베이. 6단계 주권 프레임워크 제시: ①쓰기 게이팅 ②저장 격리 ③검색 필터링 ④거버넌스 정책 ⑤감사 추적 ⑥폐기 프로토콜.

- **Multi-Layered Memory Architectures (arXiv:2603.29194)** — 장기 컨텍스트 유지를 위한 다층 메모리 아키텍처 실증 평가. 계층적 압축·우선순위 기반 보존 전략이 단순 윈도우 슬라이딩보다 장기 성능 유지 측면에서 유의미하게 우수.
- 이번 주(6/15~17) 새 arXiv 논문은 미확인 — 기존 연구 정착·인용 단계
- 🔗 [Mnemonic Sovereignty (arXiv)](https://arxiv.org/abs/2604.16548) · [Multi-Layered Memory (arXiv)](https://arxiv.org/html/2603.29194v1) · [Memory Mechanisms Survey (arXiv:2603.07670)](https://arxiv.org/abs/2603.07670)
- 🧠 **Claude가 배울 것:** Mnemonic Sovereignty의 "쓰기 게이팅 + 폐기 프로토콜" 6단계는 내 MEMORY.md 유지 정책에 직접 적용 가능 — 스테일 항목 탐지 + 삭제 절차를 명시적 워크플로우로 정형화해야.
- 👤 **내가 알 것:** LTM 보안이 에이전트 안전의 다음 전선으로 부상 중. 우리 파일 기반 메모리에도 "외부 주입(prompt injection via memory)" 방어 레이어 고민 시작.

## 📓 Obsidian / PKM / 로컬 LLM

**5대 로컬 LLM 플러그인 2026 비교** — Obsidian v1.13.x + Ollama 환경에서 검증된 플러그인 5종: ①Smart Connections(~5,000 Discord 멤버, 최다 커뮤니티), ②Copilot, ③Text Generator, ④Local GPT, ⑤BMO Chatbot. Smart Connections가 활성 커뮤니티 규모 1위.

- Bases 오프라인 DB: Notion 스타일 뷰 완전 오프라인 동작 — Ollama와 조합 시 에어갭 PKM 완성형
- AI 코딩 에이전트 연동 시 지식관리 오버헤드 30~40% → 10% 미만으로 감소 보고
- Karpathy LLM Wiki 패턴: raw→정제→구조화 마크다운으로 큐레이션 자동화
- 🔗 [5대 로컬 LLM 플러그인 (promptquorum)](https://www.promptquorum.com/power-local-llm/local-llm-with-obsidian-2026) · [Obsidian 2026 완전가이드 (Oflight)](https://www.oflight.co.jp/en/columns/obsidian-knowledge-management-guide-2026) · [Karpathy 패턴 (a2a-mcp)](https://a2a-mcp.org/blog/andrej-karpathy-llm-knowledge-bases-obsidian-wiki)
- 🧠 **Claude가 배울 것:** Smart Connections가 커뮤니티 지원 1위인 만큼, 우리 llm-wiki의 semantic search 실험 시 이 플러그인을 기준점으로 삼을 것.
- 👤 **내가 알 것:** Bases + Ollama = 완전 오프라인 AI-PKM 가능. 스케일 기준: Obsidian 중심 아키텍처는 ~5만 항목이 한계, 초과 시 AnythingLLM 전환 시점.
