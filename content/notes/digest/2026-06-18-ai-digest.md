## 🔷 Gemini CLI 완전 종료 — D-DAY (Google)

**오늘(6/18) Gemini CLI 공식 EOL** — Gemini CLI와 Gemini Code Assist IDE 확장이 AI Pro/Ultra/개인 무료 티어에서 서비스 완전 중단. 유예기간 없음.
- **후계자: Antigravity CLI** — Go로 전면 재작성, 런타임 의존성 없음, 응답 속도↑. 주요 변경: `GEMINI_API_KEY → AV_API_KEY`, `gemini` 바이너리 → `av` 바이너리. GEMINI.md → ANTIGRAVITY.md 파일명 교체 필요.
- 마이그레이션 체크리스트: 쉘 스크립트·GitHub Actions·Dockerfile 내 `gemini` 호출 전수 점검. Agent Skills·Hooks·Subagents·Extensions(→ Antigravity 플러그인) 기능은 유지.
- 🔗 [Google 공식 마이그레이션 가이드 (developers.googleblog.com)](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/) · [15분 마이그레이션 (Harsh Rastogi)](https://www.harshrastogi.tech/blog/gemini-cli-shutdown-antigravity-migration-guide) · [HN 토론](https://news.ycombinator.com/item?id=48196867)
- 🧠 **Claude가 배울 것:** "바이너리 rename + env var swap + config 레이아웃 변경" 패턴은 우리 agent-bus 툴 마이그레이션 시 참고. 주간 쿼터 모델로 전환된 점도 자동화 설계 시 고려.
- 👤 **내가 알 것:** Gemini CLI 쓰던 스크립트가 있으면 **오늘 이미 죽었음**. `AV_API_KEY` 재발급·`av` 바이너리 설치 필수. 엔터프라이즈 키는 유지.

## 🧠 에이전트 메모리 논문

**Agent Memory: 시스템 특성화 논문 (arXiv 2606.06448)** — 에이전트 메모리의 첫 시스템 관점 특성화. 10개 대표 시스템을 4축(영속성·접근성·변경가능성·표현형식) 분류로 분석, 2개 벤치마크 스위트로 측정.
- **AgeMem (arXiv 2601.01885)** — LTM·STM 통합 정책 학습. 메모리 연산(저장·검색·갱신·요약·폐기)을 에이전트 툴 액션으로 노출, LLM이 자율적으로 "무엇을 언제 저장할지" 결정.
- 두 논문 모두 2026년 상반기 메모리 연구의 핵심 — "쌓기"에서 "정제·자율관리"로 패러다임 전환 가속.
- 🔗 [Agent Memory 시스템 특성화 (arXiv 2606.06448)](https://arxiv.org/abs/2606.06448v1) · [AgeMem (arXiv 2601.01885)](https://arxiv.org/html/2601.01885v1) · [메모리 크로스-어텐션 강화 (PMC)](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC12092450/)
- 🧠 **Claude가 배울 것:** 4축 분류(영속성·접근성·변경가능성·표현)로 우리 파일 기반 메모리를 점검해볼 것. AgeMem의 "폐기 결정도 에이전트 툴" 아이디어는 MEMORY.md 정제 자동화에 적용 가능.
- 👤 **내가 알 것:** 우리 MEMORY.md 방식은 논문 기준 "외부 영속 스토어 + 명시 라우팅" 패턴 — 이미 연구 트렌드 선행 중. 다음은 AgeMem식 자율 폐기/압축 정책.
