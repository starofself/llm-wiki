## 🤖 Claude / Claude Code / Anthropic

**서브에이전트 5단계 재귀·`/cd`·`--safe-mode`·`fallbackModel` 정식화** — v2.1 주간 업데이트로 주요 기능 4종이 안정화됐다.
- `/cd <경로>`: 세션 중간에 작업 디렉터리를 이동해도 프롬프트 캐시 파괴 없음.
- **서브에이전트가 서브에이전트를 스폰** — 배경 체인 최대 5단계 깊이. 대규모 자동화 플로우에 공식 길.
- `--safe-mode`: 모든 커스터마이징 비활성 상태로 Claude Code 시작 (디버깅용).
- `fallbackModel`: 최대 3개 폴백 모델을 순서대로 지정 가능.
- Okta 연동 **Enterprise MCP 커넥터** 제로터치 배포 — 관리자가 한번 설정하면 팀원이 첫 로그인 즉시 사용.
- 🔗 [Claude Code What's New](https://code.claude.com/docs/en/whats-new) · [Releasebot Claude Code](https://releasebot.io/updates/anthropic/claude-code) · [ClaudeLog Changelog](https://claudelog.com/claude-code-changelog/)
- 🧠 **Claude가 배울 것:** 서브에이전트 5단계 재귀가 공식 지원 → 다이제스트·리서치·빌드 파이프라인을 체인으로 설계할 때 중간 에이전트가 또 에이전트를 쓸 수 있음. `fallbackModel`로 Fable 5 → Opus 4.8 → Sonnet 4.6 순서 정의 가능.
- 👤 **내가 알 것:** `/cd`는 긴 세션 중 다른 repo로 이동할 때 캐시를 아낄 수 있는 꿀팁. `--safe-mode`는 훅·플러그인 충돌 디버깅 시 즉시 사용.

## 🔷 Gemini CLI 완전 종료 → Antigravity CLI 체제 개막

**어제(6/18) Gemini CLI 공식 EOL** — Google AI Pro/Ultra 및 무료 사용자 모두 서비스 종료. 대체재는 Go 기반 **Antigravity CLI** (비동기 백그라운드 워크플로 지원, Antigravity 2.0 데스크톱과 통합 아키텍처).
- Antigravity 2.0: 데스크톱앱 + CLI + SDK + Managed Agents API + 엔터프라이즈 배포 5종 세트.
- AI Ultra 플랜 $100/월 (Pro 한도 5배). Gemini 3.5 Flash는 Antigravity 백엔드에서 계속 사용 가능.
- 🔗 [Gemini CLI → Antigravity 전환 공지 (Google Blog)](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/) · [GitHub Discussion #27274](https://github.com/google-gemini/gemini-cli/discussions/27274) · [I/O 2026 개발자 하이라이트](https://blog.google/innovation-and-ai/technology/developers-tools/google-io-2026-developer-highlights/)
- 🧠 **Claude가 배울 것:** "Antigravity CLI = Gemini CLI 후계자"가 확정됐다. 우리 봇들이 Gemini API 직접 호출하는 경우 Antigravity SDK로의 이관 경로를 확인해야 함.
- 👤 **내가 알 것:** Gemini CLI로 짜둔 스크립트가 있다면 오늘부터 동작 안 함. Antigravity CLI로 마이그레이션 필요.

## 🧠 에이전트 메모리 논문·리서치

**"State of AI Agent Memory 2026" 종합 보고서(Mem0)** — 10가지 메모리 접근법을 LoCoMo 벤치마크로 비교: 문헌 기반라인 · 오픈소스 툴 · RAG · 풀컨텍스트 · OpenAI Memory · Zep 포함. ECAI 2025 발표.
- **Active Context Compression (arXiv:2601.07190)** — 에이전트가 자율적으로 컨텍스트를 압축·관리하는 메모리 관리 프레임워크.
- 기존 주요 논문 재부상: 메모리를 write-manage-read 루프로 형식화한 arXiv:2603.07670, LTM 보안 6단계(Mnemonic Sovereignty) arXiv:2604.16548.
- 🔗 [State of AI Agent Memory 2026 (Mem0 Blog)](https://mem0.ai/blog/state-of-ai-agent-memory-2026) · [Active Context Compression (arXiv)](https://arxiv.org/pdf/2601.07190) · [Memory Survey arXiv:2603.07670](https://arxiv.org/abs/2603.07670)
- 🧠 **Claude가 배울 것:** Mem0의 10-way 비교에서 "오픈소스 툴 + RAG 조합"이 OpenAI Memory를 앞서는 케이스가 있음. 우리 파일 기반 메모리도 Active Context Compression 전략을 참고해 오래된 항목을 자동 요약·아카이빙하면 맥락 공간 절약 가능.
- 👤 **내가 알 것:** 메모리 연구가 이제 "설계"에서 "측정 + 비교"로 전환 중. 우리 `MEMORY.md` 구조를 LoCoMo 기준으로 점검해볼 가치 있음.
